## 1. 스펙을 검토하며 발견한 것 3가지 (먼저 확인하셔야 합니다)

### ① `Assets/` 폴더는 유니티 규칙입니다
스펙에 "프로젝트 폴더(`Assets/`)에 즉시 반영"이라고 돼 있는데, **언리얼은 `Content/`** 를 씁니다.
자동화 도구를 붙이실 때 경로를 `Content/` 로 잡으셔야 합니다. 사소해 보이지만
에셋 자동 반영 스크립트가 조용히 아무 데도 안 넣는 원인이 됩니다.

### ② 힉스필드로 "3D 모델 + 애니메이션"이 바로 나오는지 확인이 필요합니다
제가 아는 범위에서 힉스필드는 **이미지·영상 생성** 도구입니다.
스펙의 생성 대상 중 실제로 바로 쓸 수 있는 것과 아닌 것이 갈립니다:

| 스펙의 생성 대상 | 제 판단 |
|---|---|
| UI·키아트·대화창 초상화·메뉴 이미지 | **바로 가능** — 이미지 생성의 본령입니다 |
| 인트로/컷씬 영상 | **바로 가능** — 영상 모델로 만들어 UE5에 미디어로 삽입 |
| 3D 배경 **타일 텍스처** | **가능** — 단, seamless·top-down·no-shadow 3대 조건을 프롬프트에 반드시 넣어야 이어 붙였을 때 격자가 안 보입니다 |
| 3D 캐릭터/몬스터 **모델** | **확인 필요** — 리깅(뼈대)된 3D 메시가 나오는지 확인하세요. 안 나오면 컨셉 이미지를 뽑아 모델링 외주나 다른 3D 생성 도구로 넘기는 흐름이 됩니다 |
| **애니메이션**(공격·걷기·죽음) | **확인 필요** — 이건 거의 확실히 별도입니다. UE5 내장 **Mixamo 무료 모션**이나 마켓플레이스 애니메이션 팩으로 먼저 채우시길 권합니다 |

먼저 힉스필드에서 "리깅된 3D 캐릭터"를 한 번 뽑아보시고 결과를 알려주세요.
**나오면** 파이프라인을 그쪽으로 짜고, **안 나오면** 모션은 Mixamo로 가는 게 훨씬 빠릅니다.

### ③ 스펙의 작업량이 3~4배 많습니다
대시·회피·3단 콤보·2단 점프·레벨업·퀘스트·대화·씬 전환·컷씬·BGM 8종은
각각이 독립된 시스템입니다. 전부 병렬로 손대면 **아무것도 완성되지 않은 채 3개월**이 갑니다.
순서를 아래처럼 제안합니다.

## 3. 스펙에서 이미 반영해둔 것

전투 코어를 쓸 때 나중에 붙일 것들을 미리 연결점으로 뚫어놨습니다. **C++를 다시 안 고쳐도 됩니다.**

| 스펙 항목 | 준비해둔 연결점 |
|---|---|
| 타격감·피격 반응 | `Poise`(경직저항) · `HitStopSeconds` · `KnockbackStrength` — BP에서 숫자만 조정 |
| 이펙트 (피 튀김·카메라 흔들림) | `BP_OnHitReaction`, `BP_OnAttackLanded`, `BP_OnDeath` — 블루프린트에서 붙입니다 |
| SFX | `AttackSound` · `HitSound` · `DeathSound` — BP에 사운드만 지정 |
| 보스 연출 | `BP_OnSlamTelegraph`(바닥 붉은 원), `BP_OnPhaseChanged`(화면 흔들림·보스 UI) |
| 쇼룸 | `SG_MonsterShowroom` 액터 — 콘솔 명령으로 몬스터·모션 즉시 확인 |
| 드랍 아이템 | `SG_EliteMonster` 의 `DropActorClass` |

**C++에 Niagara를 직접 물리지 않았습니다.** 아티스트가 이펙트를 바꿀 때마다
프로그래머를 부르지 않아도 되게 하려는 의도입니다.
