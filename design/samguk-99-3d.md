# 삼국지 99일 생존 — 1막 3D 전환 기획서

> 작성일 2026-09-14 · 대상: `samguk-99-3d.html` (신규) · 기준 문서: 기획서 v0.2 7부 MVP
> 상태: **승인 대기** — 이 문서가 승인되기 전까지 게임 코드는 0줄.

## 0. 이 문서가 존재하는 이유

2D 프로토타입(`samguk-99.html`)에서 **게임 규칙은 이미 검증됐다.**
자동 플레이 결과: 단순 봇이 거점 체력 35%를 남기고 33일 완주, 함정 처치 비율 0%→6%→25% 상승.

따라서 3D 전환은 "처음부터 다시 만들기"가 아니라 **껍데기 교체**다.
- **바뀌는 것**: 화면(2D 캔버스 → Three.js 3D 씬), 카메라, 조작 방식, 미니맵 추가
- **안 바뀌는 것**: 흐름장 경로 계산, 웨이브 구성, 자원·비용·밸런스 수치, 목표 체인, 가챠 목업

## 0-1. "실제 사물처럼"의 현실적 정의 (기대치 합의)

| 이번에 되는 것 | 이번에 안 되는 것 |
|---|---|
| 진짜 입체 사물 — 뒤로 가면 작아지고, 돌면 옆면이 보임 | 포토리얼 그래픽 (사람 얼굴·천 주름·피부) |
| 태양광 + 실시간 그림자, 밤엔 횃불 조명만 남는 어둠 | 모션캡처 애니메이션 |
| 3인칭 카메라가 장수 뒤를 따라감 | 영화급 컷신 |
| 땅·돌·나무의 질감(텍스처) | 수억 폴리곤 에셋 |

**저폴리(low-poly) 스타일**로 간다. 도형은 단순하되 **조명·그림자·색·질감**으로 입체감을 만드는 방식이다.
이유 3가지: ① 오늘 완성된다 ② 폰에서도 60fps가 나온다 ③ 검증용이라 버려도 아깝지 않다.

## 2. 자원 · 경제 규칙

- **자원 3종**: 목재 / 석재 / 철
- **채집 방식 2가지**
  1. 장수 자동 채집 — 자원지 34유닛 안에 서 있고 주변에 적이 없으면 자동 (버튼 없음)
  2. 병사 위임 — 역할을 목재/석재로 지정하면 자원지↔거점을 왕복. 1회 8까지 운반
- **시작 자원**: 목재 60 · 석재 30 × 장수 등급 배율 (요화 130% ~ 여포 85%)
- **소비처**: 건설 · 병사 고용 · 제작
- **인구 상한**: 병영 1채당 병사 +1 (병영을 지어야 병사가 늘어나는 구조)
- **부가 재화**: 옥새 조각 — 목표 달성 +3, 웨이브 격퇴 +15/25/40, 완주 +30. **가챠 목업 전용, 현금 결제 없음**

## 3. 적 AI 행동

- **경로**: 거점에서 BFS로 계산한 흐름장(flow field)을 따라 이동. **목책을 세우면 즉시 재계산되어 실제로 우회한다.**
- **완전 포위 시**: 도달 경로가 없으면 가장 가까운 목책을 공격해 부순다 (피해 = 공격력 × 1.6)
- **우선순위**: ① 38유닛 안의 장수·병사 ② 거점 62유닛 안 → 거점 공격 ③ 그 외 → 흐름장 이동
- **함정 통과 시**: 이동속도 45%로 감속 + 초당 42 피해, 함정 내구도 초당 7 감소
- **겹침 방지**: 18유닛 안의 다른 몬스터와 서로 밀어냄

### 웨이브 구성 (9대 대란 중 1막 3회)

| 일차 | 사건명 | 수 | 체력 | 속도 | 피해 | 방향 | 예고 |
|---|---|---|---|---|---|---|---|
| 11 | 황건적의 습격 | 10 | 34 | 70 | 6 | 1방향(동) | 5초 전 화살표 |
| 22 | 산적 무리 | 18 | 46 | 78 | 8 | 2방향(동·북) | 5초 전 화살표 |
| 33 | 산적 두목 | 20 + 두목 1 | 56 / 600 | 85 / 55 | 10 / 22 | 2방향(동·북) | 5초 전 화살표 |

수·체력은 장수 등급의 **웨이브 강도 배율**을 곱한다(여포 115% = 더 강하게 몰려옴).

### 시간 구조
하루 7초 × 33일 ≈ 4분 + 웨이브 3회(각 20~40초) = **한 판 6~8분**
웨이브 중에는 일차가 멈춘다. 몬스터를 전멸시켜야 다음 날로 넘어간다.

## 4. 조작 체계 (3D라 새로 설계)

| 입력 | PC | 모바일 |
|---|---|---|
| 이동 | `W A S D` / 화살표 — **카메라 기준 방향** | 좌하단 가상 조이스틱 |
| 카메라 회전 | 화면 드래그 (건설 모드가 아닐 때) | 한 손가락 드래그 |
| 줌 | 마우스 휠 | 두 손가락 핀치 |
| 건설 | 카드 클릭 → 지면 클릭 (드래그로 연속 설치) | 카드 탭 → 지면 탭 |
| 건설 취소 | `Esc` 또는 취소 버튼 | 취소 버튼 |
| 공격·채집 | **없음 (자동)** | **없음 (자동)** |

### ⚠️ 입력 충돌 방지 (스킬 문서의 경고 반영)
- **드래그 하나에 두 기능(카메라 회전 / 건설)이 걸린다.** → **건설 카드가 선택된 상태에서만** 드래그=설치, 그 외에는 항상 드래그=카메라 회전. 모드가 화면에 항상 표시된다.
- 이동키(WASD)와 겹치는 단축키는 **만들지 않는다.** 건설은 클릭 전용.

### 카메라
- 3인칭 추격 — 장수 뒤 위쪽. 기획서 7부 1번 검증 항목("조작이 답답하지 않은가")
- 줌 아웃하면 쿼터뷰에 가까워져 **건설·방어선 설계**가 쉬워진다 (두 시점을 하나의 줌 축으로 통합)
- 장수 사망 중에는 거점을 비춘다

> 각 항목은 `self-check` 단계에서 테스트 1개가 된다. 전부 통과해야 완성.

**로직 (headless 시뮬레이션으로 검증)**
- [ ] 게임을 30초 진행하면 장수가 채집한 목재가 시작값보다 늘어난다
- [ ] 돌 곡괭이가 없으면 철광 옆에 서 있어도 철이 0에서 안 늘고, 제작 후에는 는다

- [ ] 병사가 자원지↔거점을 왕복해 자원을 실제로 내려놓는다 (**도착 판정은 거점 footprint 기준**)
- [ ] Day 11·22·33에 웨이브가 생성되고, 전멸시키면 리포트 데이터가 채워진다
- [ ] 거점 체력 0 → 패배 상태, Day 33 웨이브 격퇴 → 승리 상태
- [ ] 병사가 쓰러져도 영구 소멸하지 않고 15초 뒤 복귀한다
- [ ] 거점 반경 6타일 안에 건설 가능한 빈 칸이 40칸 이상 남는다 (**배치 교착 방지**)

**화면·조작 (실제 브라우저로 검증)**
- [ ] 브라우저 콘솔 에러·경고 0건 (부팅 → 33일 완주까지)
- [ ] WASD를 누르면 장수가 **카메라가 보는 방향 기준**으로 움직인다
- [ ] 드래그로 카메라가 회전하고 휠로 줌되며, 건설 모드에서는 드래그가 설치로 바뀐다
- [ ] 건설 카드 선택 시 지면에 설치 미리보기(고스트)가 뜨고, 불가능한 칸은 빨갛게 표시된다
- [ ] 밤이 되면 씬이 어두워지고 거점·장수 주변만 밝다
- [ ] 미니맵에 장수·거점·몬스터가 실시간으로 표시된다
- [ ] 폭 390px(모바일)에서 가로 스크롤이 없고 조이스틱으로 조작된다

**성능**
- [ ] 최악 장면에서 draw call ≤ 120, 삼각형 ≤ 15만
- [ ] 데스크톱 60fps, 모바일 30fps 이상

## 7. 성능 예산

**최악 장면 정의**: `33일 밤 — 몬스터 21기 + 병사 6 + 목책 80 + 함정 12 + 나무 120 + 바위 30 + 철광 14 + 시설 6 + 그림자 + 미니맵 갱신 동시`

| 항목 | 상한 | 지키는 법 |
|---|---|---|
| 목표 프레임 | 60fps (데스크톱) / 30fps (모바일) | 아래를 지키면 달성 |
| **Draw call** | **≤ 120** | 나무·바위·철광·목책·함정은 **InstancedMesh 1개씩** (7 draw call로 압축). 유닛만 개별(≤30) |
| 삼각형 | ≤ 15만 | 저폴리 — 나무 60면, 몬스터 120면, 바위 20면 |
| 텍스처 | 절차 생성 512px 4종, 2의 거듭제곱, 밉맵 | 외부 파일 0개 (오프라인 동작) |
| 그림자 | 방향광 1개, 2048 맵 | 모바일은 자동 OFF (`lowSpec` 경로) |
| 저사양 방어선 | SwiftShader/llvmpipe 감지 시 그림자·안티앨리어싱 OFF | 스킬 문서 7-3 반영 |

### 월드 스케일 (텍스처 반복 밀도의 근거)
2D판은 1타일 = 28px 이었다. 3D에서는 **1게임유닛 = 0.1 three 유닛**으로 환산한다.
→ 맵 128.8 × 95.2 유닛, 1타일 2.8 유닛, 장수 반지름 0.9 유닛 (사람 크기 ≈ 2유닛)
→ **땅 텍스처 repeat = 128.8 ÷ 12 ≈ 11** (스킬 문서의 "타일 하나가 8~14유닛" 규칙을 이 스케일에 적용)

**시뮬레이션 로직은 기존 게임 단위(px)를 그대로 쓰고, 렌더러만 0.1을 곱한다.** 검증된 밸런스 수치를 한 줄도 안 건드리기 위해서다.


### 프로젝트 규칙과의 충돌 및 해결
`CLAUDE.md`는 "순수 HTML + 빌드 없음 + 단일 파일"을 요구한다. 이번엔 **파일을 나눈다.**
- **지키는 것**: 빌드 도구 0개(webpack/vite 없음), `npm install` 불필요, GitHub Pages에 그대로 올라감 — CLAUDE.md가 그 규칙을 둔 **진짜 이유는 전부 지켜진다**
- **바뀌는 것**: 로직과 화면을 분리해야 `self-check`의 headless 테스트가 가능하다. 단일 파일이면 브라우저 없이 로직을 못 돌린다
- **비용**: 로컬에서 파일을 더블클릭하면 안 열린다(ES 모듈 CORS). → GitHub Pages 주소나 아티팩트 링크로 플레이. 로컬 확인은 `python3 -m http.server`

### Three.js 조달
`npm install three@0.180.0` 로 받아 `vendor/`에 **두 파일만** 복사(총 720KB). CDN 의존 없음 — 이 세션의 네트워크 정책상 CDN이 차단돼 있기도 하고, 오프라인에서도 열려야 하기 때문.

## 16. 99일 전체 구조 · 침공로 안내 · 용병 · 소리 (2026-09-15)

플레이 중 나온 요청 7건을 반영했습니다. 그중 하나는 **제 설계 누락**이었습니다.

### 16-1. 적이 어디로 오는지 보여주지 않았던 문제 ★

팀장님 질문: *"몰려오는 적들의 위치를 알 수가 없어서 어디에 목책을 놓고
함정을 놔야 할지 판단이 안 되는데, 이건 일부러 그런 건가?"*

**아닙니다. 설계 누락입니다.** 예전 코드는 공격 방향을 웨이브 **5초 전**에야
정했습니다(`startWarn` 안에서 `['E','N','S','W'].slice(0, sides)`).
목책 하나 세울 시간도 안 되는데 "길목을 좁히라"고 요구한 셈입니다.

고친 방식 — 세 겹으로 알려줍니다.

1. **방향을 게임 시작 때 전부 확정** (`S.plannedDirs`, `planDirs()`)
   9번의 대란 방향이 1일차에 이미 정해져 있고, HUD에 항상 떠 있습니다.
   동쪽은 거점에서 가장 먼 정면이라 항상 포함하고, 나머지는 웨이브마다 돌립니다.
2. **예상 침공로를 바닥에 그림** (`invasionPath()` + `updatePath()`)
   진입점에서 거점까지 **흐름장(flow field)을 그대로 따라간 길**입니다.
   추정이 아니라 몬스터가 실제로 밟을 칸입니다.
   목책을 하나 놓으면 그 자리에서 길이 휩니다 → *내 목책이 적의 길을 바꿨다*가 눈에 보입니다.
3. **스폰 위치를 진입점 ±4칸으로 모음** (`edgePoint()`)
   예전에는 가장자리 전체에 흩뿌렸습니다. 그러면 화면에 그린 경로가 거짓말이 됩니다.
   그려주는 이상, 그 길로 와야 합니다.

성능: 화살표 전부가 **InstancedMesh 1개** (draw call 1). 진입 기둥은 최대 4개.
미니맵에도 같은 경로를 점선으로 그립니다.

### 16-2. 99일 3막 구조

*"99일인데 10일 전에 게임이 끝날 것 같기도 해"* → 실제로 1막 33일만 있었습니다.

| 막 | 일차 | 배울 것 | 대란 |
|---|---|---|---|
| 1막 개척기 | 1~33 | 목책으로 길을 좁히고 함정 깔기 | 11 · 22 · 33 |
| 2막 확장기 | 34~66 | 기병·방패병 — 한 가지 방어로는 안 막힘 | 44 · 55 · 66 |
| 3막 결전기 | 67~99 | 사방 동시 공격 — 병력·성·함정 전부 | 77 · 88 · 99 |

몬스터 4종(`MONSTER_KINDS`): 졸개 / 기병(1.5배 빠름) / 방패병(체력 2.3배·피해 -30%) /
정예(체력 3.2배·피해 1.6배). 색과 실루엣(방패·투구깃)이 달라 한눈에 구분됩니다.
하루 7초 → 8초, 전체 약 13분.

### 16-3. 밸런스를 눈이 아니라 시뮬레이션으로 잡았습니다 ★

99일로 늘리고 **자동 플레이로 9번의 대란을 전부 돌려봤습니다**
(`design/tests/` 밖의 일회용 probe). 처음 결과:

```
잘준비 | 88일 조조의 정예 | ❌ 함락    ← 최대한 준비해도 못 넘김
잘준비 | 99일 최후의 대란 | ❌ 함락
```

원인은 난이도가 아니라 **후반에 성장할 거리가 없다는 것**이었습니다.
무기 강화가 3단계에서 끝나고 그 뒤 60일 동안 강해질 방법이 없었습니다.
적만 깎으면 "쉬워졌을 뿐"이라 3막 장비를 넣었습니다.

- 무기 강화 3단계 → **6단계** (단계가 오를수록 철·가죽이 더 듦)
- **강철 가시** — 함정 피해 +70%, 내구도 +60% (이미 깔린 함정에도 적용)
- **망루 강화** — 철옹성 망루 피해 2배·연사 +40%
- **군기(軍旗)** — 병사·용병 공격 +50%, 체력 +40% (이미 고용한 병력에도 적용)
- 철옹성 체력 2700 → 3200

다시 측정한 결과 — 준비한 만큼 갈리는 곡선이 나왔습니다.

| 준비 | 버티는 한계 | 함정 처치 비율 |
|---|---|---|
| 방치 (안 지음) | 33일까지, 44일 함락 | 0% |
| 보통 (목책 일부·함정 4) | 44일까지, 55일 함락 | 0~6% |
| **잘 준비** (사방 목책 + 문마다 함정 + 3막 장비) | **99일 완주** (거점 피해 1864/3200) | **23~35%** |

보통과 잘 준비의 차이는 대부분 **"사방을 둘러싸고 문을 네 개 내는가"** 였습니다.
그 판단을 가능하게 해주는 것이 바로 16-1의 침공로 표시입니다. 두 작업이 한 몸입니다.

### 16-4. 용병 (계약직)

병사는 자원으로 뽑고 병영 한도에 묶입니다.
용병은 **옥새 조각**으로 뽑고 한도가 없는 대신 **18일 계약**이 끝나면 떠납니다.
→ 옥새 조각을 쓸 곳이 생기고, "지금 손이 모자라다"를 돈으로 푸는 길이 열립니다.

| 용병 | 값 | 특징 |
|---|---|---|
| 🧺 채집 용병 | 6 | 싸우지 않고 **밤에도** 캡니다. 병사의 2배 속도 |
| 🏹 궁수 용병 | 10 | 사거리 120 — 목책 뒤에서 안전하게 |
| 🛡️ 방패 용병 | 12 | 체력 260·받는 피해 -35% — 적을 붙잡아 둠 |

병사·용병 역할도 넓혔습니다: 목재 → 석재 → **약초 → 철**(곡괭이 필요) → 방어.
철을 병사에게 맡길 수 있게 되면서 장수가 중앙 철광을 혼자 오가는 부담이 사라졌습니다.

### 16-5. 부활 시간 표시

`h.respawn` / `s.downT` 값은 이미 있었는데 **화면에 안 보여줬습니다.**
멈춘 것처럼 느껴지는 원인이었습니다.
- 장수 — 화면 중앙에 큰 숫자 + 진행 막대, HUD 이름 옆에도 남은 초
- 병사·용병 — 머리 위에 `🩹 궁수 용병 복귀 8.3초`, 목록에도 표시

검수 중에 **부활 즉사 루프**를 발견했습니다. 되살아난 자리 옆에 적이 있으면
그 자리에서 또 죽습니다. `RESPAWN_INVULN = 1.6초` 무적을 넣었습니다.

### 16-6. 우클릭 취소

처음에 2단계(조준만 풀기 → 카드 풀기)로 만들었더니, 마우스가 화면 위에 있으면
`pointermove` 가 곧바로 다시 조준을 잡아서 **두 번 눌러야** 풀렸습니다.
**한 번에 건설 모드에서 완전히 빠져나오게** 고쳤습니다. Esc 도 그대로 됩니다.

### 16-7. 소리 — `js/audio.js` (음원 파일 0바이트)

빌드도 CDN도 없는 프로젝트라 **브라우저가 그 자리에서 합성**하게 만들었습니다.
용량 0, 저작권 0, 로딩 0초.

타격음 한 방은 세 겹입니다 — ① 툭(짧은 잡음) ② 둥(낮은 사인파) ③ 쨍(금속음, 치명타만).
이 셋의 길이와 세기를 바꿔 검·활·방천화극을 구분했습니다.
같은 소리가 겹쳐 터지지 않게 **최소 간격**과 **동시 발음 18개** 제한을 뒀습니다.

배경음악은 **5음계(펜타토닉) 위의 절차적 연주**입니다. 5음계는 아무 음을 겹쳐도
불협이 잘 안 나고 국악 평조와 음 구성이 겹쳐 삼국지 분위기에 맞습니다.
낮은 느린 아르페지오, 밤은 북 + 낮은 오스티나토. 같은 음계라 이어 들립니다.

### 16-8. 출전 전 뽑기 · 보석 상점

타이틀에서 바로 열립니다(🎲 출전 전 뽑기). 옥새 조각 10 또는 **보석** 30,
**10연차** 270(1회분 할인). 확률표는 코드의 `GACHA` 배열 하나에서만 나오고
화면 표와 같은 값입니다 — 두 곳이 어긋나면 그게 확률 조작입니다.

**결제는 붙이지 않았습니다.** 보석 팩 버튼은 결제 창 없이 그냥 지급하고,
화면에 "실제 결제가 일어나지 않는다"고 적어뒀습니다.
한국에서 확률형 아이템은 **확률 전체 공개가 법적 의무**(게임산업법 제33조)라
확률표를 상점에 항상 띄웁니다. 실제 출시 때는 구글·애플 결제와
청약철회·환불 안내를 함께 붙여야 합니다.

## 17. 자원 표시 버그 · 궁극기 · 건설 UI · 도감 각성 (2026-09-15)

팀장님이 플레이하며 물어본 4건과 개선 요청 3건. **그중 하나는 진짜 버그였습니다.**

### 17-1. "나무랑 돌밖에 안 보여" — 렌더러 버그 ★

`refreshNodes()` 의 분기가 이랬습니다.

```js
if (n.type === 'wood') { ... }
else if (n.type === 'stone') { ... }
else { /* 철광으로 그림 */ }      // ← herb 가 여기로 떨어짐
```

약초 26포기가 **철광 인스턴스에** 그려지고 있었습니다. 게다가 인스턴스 용량은
`counts = { wood, stone, iron }` 으로 잡아서 **철광 14개분**밖에 없는데
철광 14 + 약초 26 = 40개를 쓰려 했습니다. 용량을 넘는 것들은 그냥 안 그려집니다.

즉 **약초는 화면에 아예 없었고, 철광도 그냥 회색 돌이라 구분이 안 됐습니다.**
팀장님이 못 찾은 게 당연합니다.

고친 내용:
- `counts` 에 `herb` 추가, 약초·철광 각각 제 인스턴스를 가짐
- **약초** — 낮고 둥근 초록 덤불 + 옅은 꽃 (나무·바위와 실루엣이 확실히 다름)
- **철광** — 어두운 바위 위로 삐져나온 **주황 결정**(emissive). 멀리서도 구분됨
- **미니맵에 자원지 점** 추가 — 목재 녹색 / 석재 회색 / 철 주황 / 약초 연두

### 17-2. "목책으로 길이 바뀌던데 이건 어떻게 판단해?"

정확히 그 판단을 숫자로 만들어 붙였습니다.

- `pathTileSet(S)` — 다음 웨이브가 지나갈 칸의 집합
- `trapsOnPath(S)` — 깔아둔 함정 중 몇 개가 그 위에 있는가
- HUD에 상시 표시: **`함정 3/5 개가 침공로 위`** (0개면 붉게 "한 마리도 못 잡습니다")
- 함정을 놓기 전 미리보기에 **`✓ 침공로 위입니다`** / **`⚠ 벗어났습니다`**
- 미니맵에서 경로를 벗어난 함정은 **회색**으로

판단 규칙 자체는 한 줄입니다 — **길이 바뀌면 함정도 따라가야 합니다.**
목책은 길을 *막는* 게 아니라 *몰아가는* 도구이고, 몰아간 그 자리에 함정이 있어야 합니다.

### 17-3. 회피 제거 → Space = 장수별 궁극기

팀장님이 "회피 구르기는 없어도 될 것 같다"고 해서 통째로 뺐습니다
(`dodgeRoll`, `DODGE_*` 전부 삭제).

붉은 예고는 그대로 둡니다. **구르는 대신 걸어서 물러나면 빗나갑니다**

Space 에는 장수마다 다른 궁극기가 들어갔습니다. 재사용 30초, **쓰는 동안 무적** —

| 장수 | 궁극기 | 효과 |

| 요화 | 천지개벽 | 주변 전체 ×5.5, 무적 1.3초 |

## 18. 건설 회귀 수정 · 장수 외형 · 반복 시뮬레이션 (2026-09-15)

### 18-1. 건설이 아예 안 되던 회귀 ★

팀장님이 *"이제 건설이 안 되는 것 같아"* 라고 해서 **사람이 누르는 그대로** 재현해 봤습니다.

```
❌ 건설 바를 클릭하면 목책이 선택된다
❌ 땅을 클릭하면 "여기에 지을까요?" 가 뜬다
❌ 확인을 누르면 목책이 실제로 지어진다 — 0 → 0
```

원인은 **한 줄**이었습니다. 17-4에서 건설 바를 `#stage` 안으로 옮기면서
`fromUI` 가드 목록에 `#buildDock` 을 넣지 않았습니다.

```js
const fromUI = e => e.target.closest('#buildConfirm, #hud, #minimapWrap, …');
//                                    ↑ #buildDock 이 없음
```

건설 바가 `#stage` 안에 있으니, 버튼을 누르면 `pointerdown` 이 stage 까지 올라오고
`stage.setPointerCapture()` 가 걸립니다. **포인터가 stage 로 넘어가면서 버튼의 click 이
아예 발생하지 않았습니다.** 로직(`Sim.tryBuild`)은 멀쩡한데 조작만 막힌 상태였습니다.

**재발 방지** — `design/tests/ui-build-test.mjs` 를 새로 만들었습니다.
로직 검수는 `Sim.tryBuild` 를 직접 부르므로 이런 UI 사고를 절대 못 잡습니다.
그래서 **마우스로 실제로 눌러보는** 검수를 따로 둡니다(12개 항목).

## 19. 반복 시뮬레이션 7~9회차 — 설계 결함 셋 (2026-09-15)

장수 6명 × 3~4판씩 자동으로 돌려 통계를 냈습니다. 한 판만 보면 지도 운이 섞여
"게임이 문제인지 운이 문제인지" 구분되지 않기 때문입니다.

### 19-1. 목표가 중간에 막히면 그 뒤가 전부 멈췄습니다 ★

7회차 통계에서 이런 판이 나왔습니다.

```
황충   성 3단계 · 무기 6단계 · 99일 도달   …그런데 목표는 2/23
```

`updateObjective` 가 **지금 목표 하나만** 봤기 때문입니다.

```js
const o = OBJECTIVES[S.objIdx];
if (o && o.ok(S)) { S.objIdx++; … }     // ← 현재 목표가 안 되면 그 뒤는 영원히 안 봄
```

예를 들어 **함정 없이 11일을 막아내면** "가시함정 2개" 목표에서 멈추고,
그 뒤 15개 목표를 하나도 못 봅니다. 플레이어가 순서를 다르게 진행할 자유가
있는데, 안내는 한 줄로만 흐르게 돼 있던 것입니다.

→ 뒤쪽에 이미 달성된 목표가 있으면 **거기까지 건너뜁니다**(보상도 함께).

### 19-2. 함정이 후반에 무력했습니다 ★

함정 한 칸이 실제로 얼마나 일하는지 표로 뽑아봤습니다.

| 웨이브 | 적 체력 | 함정만으로 잡으려면 (기본/강철) |
|---|---|---|
| 11일 졸개 | 34 | 0.9칸 / 0.5칸 |
| 33일 졸개 | 56 | 1.8칸 / 1.1칸 |
| 99일 졸개 | 140 | 4.8칸 / 2.8칸 |
| **99일 정예** | **448** | **17.2칸 / 10.1칸** |

피해가 **초당 42 고정**인데 적 체력은 13배가 됩니다. 문 안쪽에 3칸을 깔아도
3막 정예는 긁히지도 않습니다. "함정의 가치를 배운다"는 기획 의도가 후반에 무너져 있었습니다.

→ 고정 피해에 **최대 체력 비례 피해(초당 5%)** 를 얹었습니다.
초반에는 거의 티가 안 나고(11일 졸개 기준 초당 +1.7), 후반 정예에게 크게 듣습니다.
감속도 ×0.45 → ×0.38 로 강화해 함정 위에 더 오래 머물게 했습니다.

```
99일 정예 17.2칸 → 5.6칸
```

### 19-3. 달성할 수 없는 목표를 걸어두고 있었습니다 ★

목표 10번이 이랬습니다.

적이 약해서 **장수 혼자 93%를 잡아버리기 때문**입니다. 밸런스 문제가 아니라
그 구간의 자연스러운 결과입니다.

## 20. 게임이 11일에서 통째로 멈추던 버그 (2026-09-16) ★★

팀장님이 *"갑자기 멈춘 듯"* 하며 올려주신 화면 한 장이 결정적이었습니다.

### 20-1. 화면이 말해준 것

HUD 위아래가 이렇게 찍혀 있었습니다.

```
낮 · 채집과 건설          ← hPhase
전투 중 — 남은 적 0       ← dayTimer
```

이 둘이 **동시에** 뜰 수 있는 상태는 하나뿐입니다 — `phase === 'report'`.
hPhase 는 night/warn 이 아니면 "낮" 이라 찍고, dayTimer 는 day/warn 이 아니면 "전투 중" 이라 찍기 때문입니다.
그리고 `update()` 는 첫 줄이 이렇습니다.

```js
if (S.over || S.phase === 'report') return;
```

→ **리포트 단계인데 리포트 화면이 안 떠 있으면 게임은 영구 정지합니다.**
스킬 쿨다운 숫자(3.1 / 14.4 / 29.4)가 얼어붙어 있던 것도 같은 이유입니다.

### 20-2. 진짜 원인 — 사라진 `id` 하나

브라우저에서 웨이브를 실제로 치러 재현했더니 이 오류가 나왔습니다.

```
TypeError: Cannot set properties of null (setting 'textContent')
    at refreshHUD (js/main.js:335)
```

17-5 에서 넣은 "다음 날 타이머" 코드가 이랬습니다.

```js
if (S.phase === 'day') {
  $('hDayLeft').textContent = left.toFixed(1);                       // ①
  dt.querySelector('.dt').innerHTML = `다음 날까지 <b id="hDayLeft">…</b>초`;   // ②
} else if (warn) {
  dt.querySelector('.dt').innerHTML = `<b …>몰려오기까지 …</b>`;      // ③ ← id 를 지움
} else {
  dt.querySelector('.dt').innerHTML = `<b …>전투 중</b> — 남은 적 …`; // ④ ← id 를 지움
}
```

밤·해질녘 분기(③④)가 `.dt` 를 통째로 갈아엎어 `<b id="hDayLeft">` 를 지웁니다.
**밤이 끝나고 다시 낮이 되는 첫 프레임**에 ①이 `null.textContent` 로 터집니다.

### 20-3. 왜 한 줄의 오류가 게임 전체를 죽였나

```js
function frame(ts) {
  … refreshHUD() …
  requestAnimationFrame(frame);   // ← 마지막 줄
}
```

**다음 프레임 예약이 함수의 마지막 줄**에 있었습니다. 중간에서 오류가 나면
그 줄에 도달하지 못하고, **다음 프레임이 아예 예약되지 않습니다.** 루프가 끊깁니다.
화면은 마지막 그림 그대로 멈추고, 입력도 시뮬레이션도 전부 정지합니다.

### 20-4. 세 겹으로 고쳤습니다

1. **원인** — `.dt` 의 innerHTML 을 한 번만 쓰고, 사라질 수 있는 `id` 는 참조하지 않습니다.
   리포트 단계용 문구(`웨이브 리포트`)도 따로 뒀습니다.
2. **루프 보호** — `requestAnimationFrame(frame)` 을 `finally` 로 옮겼습니다.
   이제 화면 갱신에서 무슨 오류가 나도 **루프는 계속 돕니다.**
   오류는 삼키지 않고 토스트로 띄웁니다 — 조용히 이상해지는 게 제일 나쁩니다.
3. **갇힘 방지** — 1.5초마다, 리포트 단계인데 리포트 화면이 없으면 다시 엽니다.
   화면을 여는 쪽에 어떤 문제가 생겨도 플레이어가 갇히지 않습니다.

### 20-5. 왜 검수가 못 잡았나 — 그리고 채운 구멍

- 로직 검수(`sim-test`)는 브라우저를 안 씁니다 → HUD 오류를 볼 수 없음
- 건설 검수(`ui-build-test`)는 **웨이브를 치르지 않습니다** → 밤→리포트→낮 경로를 안 밟음

**`design/tests/ui-wave-test.mjs`** 를 새로 만들었습니다(19개 항목).
11·22·33일 웨이브를 실제로 치르고, 리포트를 닫고, **낮으로 되돌아온 뒤에도
게임 시각이 계속 흐르는지** 확인합니다. 리포트 화면을 강제로 숨겨 "갇힌 상태" 를
만든 뒤 되살아나는지도 봅니다.

> 배운 것 — 상태를 **오가는** 경로는 한쪽 방향만 밟아보면 안 됩니다.
> 낮→밤은 매번 테스트됐지만 밤→낮은 한 번도 테스트되지 않았고, 버그는 정확히 거기 있었습니다.

## 21. 실제 플레이 피드백 반영 — "뭘 해야 하지" 를 없애기 (2026-09-16)

팀장님이 직접 해보고 준 네 가지. 전부 맞는 지적이었습니다.

### 21-1. 자원이 있는 칸에는 아무것도 못 지었습니다 ★

`canBuildAt` 이 `occ !== OCC_EMPTY` 면 무조건 막았습니다. 나무·바위는 다 캐도
24초 뒤 되살아나므로 `OCC_NODE` 가 유지되고, **그 칸은 영원히 건설 불가**였습니다.

재보니 **거점 반경 7칸의 11%** 가 그렇게 막혀 있었습니다. 목책을 한 줄로 세우려는데
하필 나무가 걸리면 그 자리에 구멍이 나고, 적은 정확히 그 구멍으로 들어옵니다.

→ **밀어내고 지을 수 있게** 했습니다. 남은 자원의 **절반을 챙기고** 자원지는 사라집니다.
"이 나무를 벨까, 자원으로 남길까" 라는 선택이 생깁니다.

### 21-2. "하면서 내가 뭘 해야 하지 라는 생각이 많이 든다" ★★

가장 중요한 신호였습니다. 목표 한 줄로는 부족합니다. 플레이어가 실제로 묻는 것은
**"지금 당장 뭘 눌러야 하나"** 이고, 그 답은 상황마다 다릅니다.

화면 왼쪽에 **「지금 할 일」** 패널을 붙였습니다. 우선순위대로 세 가지가 항상 떠 있고,
**누르면 바로 그 행동으로 넘어갑니다.**

| 상황 | 뜨는 할 일 |
|---|---|
| 1일차 | 🔨 대장간 · ⛺ 병영 · 🪵 목재 캐기 |
| 대장간 완료 | ⛏️ 돌 곡괭이 · ⚔️ 무기 강화 · 🦺 가죽 갑옷 |
| 대란 2일 전 | 🔻 함정 깔기 · 🧱 목책 · 🗡️ 병사 고용 |
| 밤 | ⚔️ 적 N마리를 막으세요 |

각 항목에 **필요 자원과 보유량**이 초록/빨강으로 붙습니다(`🪵69/40 🪨35/18`).
채집 항목을 누르면 **가장 가까운 자원지 쪽으로 화살표**가 뜹니다 — 화면 밖이면
가장자리에 방향과 거리(`🪵 12칸 →`)로 붙습니다.

### 21-3. "나무는 너무 잘 되고 돌은 반대로 너무 필요하다" ★

맞습니다. 지도에 나무가 돌보다 3배 많은데 **캐는 속도까지 더 빨랐습니다.**

| | 전 | 후 |
|---|---|---|
| 채집 속도 | 나무 4 / 돌 3 | **나무 3.4 / 돌 4.2** |
| 자원지 하나의 양 | 나무 26 / 돌 26 | **나무 22 / 돌 30** |
| 함정 | 목5·석10 | **목10·석7** |
| 병영 | 목25·석15 | **목35·석10** |
| 대장간 | 목30·석25 | **목40·석18** |
| 석성 | 석60·목40 | **석45·목70** |
| 철옹성 | 석120·철30 | **석85·목90·철25** |

돌은 귀한 대신 **빨리 캐지고 한 번에 많이 나옵니다.** 비용은 **목재 쪽으로 옮겼습니다** —
지도에 나무가 많으니 그게 맞습니다. 자동 플레이에서 목재/석재 누적 비율이 **1.17** 로
거의 균형이 됐습니다.

### 21-4. 특수 재료 — ⭐ 정수(精髓)

*"나무나 돌을 채취하다가 확률적으로 특수 재료도 추가로 얻게 해달라"*

**정수**를 넣었습니다. 무엇을 캐든 낮은 확률로 함께 나옵니다
(나무 1.2% · 돌 2% · 약초 2% · **철 5%**).

쓸 곳은 하나지만 강력합니다 — **모자란 자원을 대신합니다.**
정수 1개가 일반 자원 6을 대신하고, 건설·제작·성 업그레이드 어디에나 통합니다.
돌이 없어도 정수로 성을 올릴 수 있습니다.

> 왜 이렇게 설계했나 — "자원이 모자라 아무것도 못 하는" 막힘이 이 게임에서 가장
> 답답한 순간입니다. 새 재료를 새 레시피로만 쓰게 하면 복잡해지기만 합니다.
> **막힘을 저절로 풀어주는 역할**을 주면 하나로 두 문제를 풉니다.
> 단, 가죽은 정수로 못 삽니다 — 그러면 밤에 안 싸워도 되니까요.

### 21-5. 같은 실수를 두 번 했습니다 — 그리고 구조로 막았습니다

「지금 할 일」패널을 붙였더니 **클릭이 전혀 먹지 않았습니다.**
18-1 에서 건설 바로 똑같이 겪은 일입니다 — `#stage` 안에 얹은 UI 를 `fromUI`
목록에 빠뜨리면, `pointerdown` 이 stage 로 올라가 `setPointerCapture` 가 걸리면서
**버튼의 click 이 아예 발생하지 않습니다.**

선택자를 하나씩 적는 방식이 문제였습니다. 이제 화면 안 UI 는 전부 **`data-ui`** 표시를
달고, 가드는 그것 하나만 봅니다.

```js
const fromUI = e => !!(e.target.closest('[data-ui]'));
```

그리고 검수를 추가했습니다 — **`#stage` 안에서 클릭을 받는 요소 중 `data-ui` 가
없는 것이 있으면 실패**합니다. 세 번째는 없습니다.

## 22. 왜 5분 만에 찾는 버그를 못 찾았나 — 검수 체계를 다시 짰습니다 (2026-09-16)

팀장님 질문: *"왜 내가 5분도 안 걸려 확인되는 버그를 너는 반복하면서도 못 찾는 거야?"*

### 22-1. 정직한 이유

**제 검수는 제가 만든 기능만 확인했습니다.** 기능을 하나 붙이면 그 기능의 테스트를
씁니다. 그런데 **버그는 기능과 기능 사이에서 납니다.**

| 사고 | 어디서 났나 |
|---|---|
| 건설이 통째로 막힘 | 건설 로직 ✅ · **UI를 화면 안에 얹은 지점** ❌ |
| 11일에서 게임 정지 | 낮→밤 ✅ · **밤→낮 복귀** ❌ |
| 할 일 패널 클릭 무반응 | 할 일 계산 ✅ · **또 같은 지점** ❌ |
| 병사를 한 명도 못 뽑음 | 고용 로직 ✅ · **버튼이 화면 밖** ❌ |

전부 "각 기능은 멀쩡한데 이어 붙인 자리가 끊긴" 형태입니다.
저는 제가 깐 길만 걸었고, 팀장님은 그냥 플레이하면서 그 사이를 밟았습니다.

### 22-2. 그래서 검수를 여섯 겹으로 다시 짰습니다

`bash design/tests/run-all.sh` 하나로 전부 돕니다.

| | 검수 | 무엇을 잡는가 |
|---|---|---|
| ① | **정적 전수 점검** (신규) | 코드가 부르는 id ↔ 화면의 id 대조, 죽은 요소, 없는 효과음 |
| ② | 로직 검수 | 규칙이 맞는가 (214개) |
| ③ | 건설 조작 검수 | 실제로 마우스로 눌러 지어지는가 (15개) |
| ④ | 웨이브 진행 검수 | 밤 → 리포트 → **낮 복귀** (19개) |
| ⑤ | **전수 클릭 점검** (신규) | 화면의 **모든 버튼**을 여러 상황에서 눌러봄 (23개) |
| ⑥ | **긴 플레이 점검** (신규) | 브라우저에서 **99일 완주 + 재시작** (8개) |

**합계 290개.**

### 22-3. 새 검수가 바로 잡아낸 것들

**① 정적 점검** — 돌리자마자 셋이 나왔습니다.
- **`upgrade` 효과음이 정의돼 있지 않았습니다** — 성을 올려도 소리가 안 났습니다
- 화면 안 UI 중 `data-ui` 표시가 빠진 것들
- 아무도 안 쓰는 죽은 id 2개

**⑤ 전수 클릭** — 진짜 UX 문제를 잡았습니다.
- **병사·용병 고용 버튼이 화면 밖(스크롤 필요)** 이었습니다.
  팀장님 스크린샷에서 **병영을 2채 짓고도 병사가 0명**이었던 이유입니다.
  버튼을 못 본 것입니다.

**⑥ 긴 플레이** — 99일을 끝까지 돌려 확인했습니다. 리포트 9회 전부 정상,
멈춤 0회, 화면 위 요소 누수 없음, 끝난 뒤 재시작도 정상.

### 22-4. 병력 창 — 화면 안에서 바로 고용

건설 바에 **🗡️ 병력 (숫자키 6)** 을 넣었습니다. 누르면 화면 안에 작은 창이 열려
**병사와 용병 3종을 바로 고용**합니다. 각 항목에 비용·정수 대체 가능 여부·
왜 못 뽑는지(정원 참 / 병영 없음 / 옥새 부족)가 함께 나옵니다.

### 22-5. 검수 자체의 오류도 걸러냈습니다

새 검수를 처음 돌렸을 때 7개가 실패했는데, 그중 **6개는 검수가 틀린 것**이었습니다.
- 일시정지를 눌러놓고 "게임이 안 돈다" 고 판정
- 마지막 대란을 막아 **게임이 끝난 것**을 "멈췄다" 고 판정
- `pointer-events:none` 이라 클릭을 안 받는 요소에 표시가 없다고 판정

검수가 거짓 경보를 내면 **진짜 실패를 무시하게 됩니다.** 전부 정확하게 고쳤습니다.

> 배운 것 — 기능마다 테스트를 쓰는 것으로는 부족합니다.
> **"사람이 실제로 하는 일"** 을 그대로 하는 검수가 따로 있어야 합니다.
> 모든 버튼을 누르고, 끝까지 플레이하고, 상태를 오가는 검수.

## 23. 제작 정리 — 11개 → 8개, 5단 사슬 제거 (2026-09-16)

팀장님 말씀: *"이제 많은 요소들이 들어가다 보니 좀 정리가 필요할 것 같아.
무기 업글 제작 너무 정신없다. 네가 좀 판단해서 줄일 거 줄이고 검증해줘."*

### 정신없던 이유 — 세어 보니 숫자로 나왔습니다

| | 정리 전 | 정리 후 |
|---|---|---|
| 제작 항목 | **11개** | **8개** |
| 무기 강화 단계 | **6단계** (단계마다 +25%) | **3단계** (단계마다 +50%) |
| 제작을 위해 눌러야 하는 횟수 | 최대 **17번** | 최대 **10번** |
| 가장 깊은 선행 사슬 | **5단** (가죽 갑옷 → 철 갑옷 → 강철 가시 → 망루 강화 → 군기) | **1단** (갑옷 → 중갑) |
| 효과가 없는 항목 | **1개** (🔥횃불) | 0개 |

무기 강화의 **최종 수치는 그대로 +150%** 입니다. 같은 곳에 도착하는데
여섯 번 누르던 것을 세 번으로 줄인 것뿐입니다.

### 정리 원칙 셋

1. **효과가 없는 것은 없앤다** — 🔥횃불은 코드 전체에서 참조가 **0회**였습니다.
   만들어도 아무 일도 일어나지 않는 항목이 목록에 앉아 있었습니다.
2. **비슷한 것은 합친다** — 돌 곡괭이 + 철 곡괭이 → **곡괭이** 하나.
   "철을 캐려면 돌 곡괭이, 더 빨리 캐려면 철 곡괭이" 는 구분할 값어치가 없었습니다.
3. **사슬 대신 성 단계로 잠근다** — 망루 강화는 삭제하고 철옹성에 기본 포함시켰습니다.
   남은 시설 강화 둘은 선행 제작이 아니라 **성 단계**(석성 / 철옹성)로만 잠급니다.
   사슬은 "왜 잠겨 있는지" 를 알려면 위로 네 칸을 거슬러 올라가야 합니다.

### 정리 후 목록 (3묶음)

- **장비** — ⛏️곡괭이 · 🔪사냥용 칼 · ⚔️무기 강화(★3) · 🦺갑옷 · 🛡️중갑
- **시설 강화** — 🗡️강철 가시(석성 필요) · 🚩군기(철옹성 필요)
- **소모품** — 🧪치유약

### 화면도 같이 고쳤습니다

- 만들 수 있는 것이 **맨 위**, 잠긴 것이 아래, 이미 만든 것은 **한 줄로 접힘**
- 못 만드는 이유를 **그 줄에** 적음 (🔒 석성이 필요합니다)
- 무기 강화는 지금 누르면 어떻게 되는지를 적음 — `공격력 +50% → +100%`
- 자원 칩은 모자라면 빨강, 충분하면 초록. ⭐정수로 메울 수 있으면 그것도 표시

### 이번에도 같은 종류의 구멍을 냈습니다

새 화면을 짜면서 **줄 전체를 `<button>` 으로 만들어 놓고 "만들기" 딱지를 안 붙였습니다.**
누르면 만들어지긴 하는데, 바로 위 「성 올리기」 줄에는 `올리기` 버튼이 보이니까
플레이어는 제작 줄에서도 버튼을 찾다가 "왜 못 만들지?" 하게 됩니다.

스크린샷을 찍어 보고서야 찾았습니다. 그래서 **⑥ 제작소 점검**(`audit-craft.mjs`, 14개)을
검수에 추가했습니다 — 만들 수 있는 줄에 딱지가 **실제로 있는지**, 그 **딱지를 마우스로 눌러**
정말 제작이 되는지까지 봅니다.
